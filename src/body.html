Student Guide: Claude and GitHub Setup

November 11, 2026 · Written by Claude and Hilary Havens

This guide shows you how to connect each Claude tool we use in class to GitHub, so that your work ends up in a GitHub repository and, if you like, on a public website. Everyone starts with Part 1 (a GitHub account and a repository). Then follow only the part for the tool you are using.

Part 1: Your GitHub account and repository (everyone)

Every tool in this guide saves your work to a GitHub repository, so everyone does these steps first. They take about 10 minutes and need only a browser.

Make a GitHub account

  1. Go to github.com/signup and create a free account. Choose a username you are happy to have in a public web address: your sites will live at https://YOUR-USERNAME.github.io/....
  2. Confirm your email address when GitHub asks.

Make a repository

A repository ("repo") is a project folder that GitHub stores and keeps a history of. The examples in this guide use a repository named dh_class, but yours can have any name.

  1. Sign in at github.com, click + at the top right, and choose New repository.
  2. Type a name under Repository name.
  3. Set Choose visibility to Public. (GitHub Pages websites on free accounts need a public repository.)
  4. Switch Add README to On, and click Create repository.

Your repository is public, so anyone with the link can see it. Do not put your address, phone number, student ID, or anything else private in it.

Upload files on github.com

You can always add files without any other app:

  1. Open your repository and click Add file > Upload files.
  2. Drag in your files and click Commit changes.
  3. To replace a file later, upload the new version with the same name. GitHub keeps the old version in its history.

To make a single new file by pasting text (useful with the UT AI Hub in Part 5), click Add file > Create new file, type the file name (for example, index.html), paste the text into the large box, and click Commit changes.

Optional: GitHub Desktop (Mac and Windows)

GitHub Desktop is a free app that keeps a folder on your computer in step with your GitHub repository. Parts 3 and 4 use it.

  1. Download it from desktop.github.com, install it, and open it.
  2. Click Sign in to GitHub.com, log in in the browser window that opens, and click Authorize. Back in GitHub Desktop, accept the suggested name and email.
  3. To get an existing repository onto your computer, choose File > Clone repository, pick it, and click Clone.
  4. After files change on your computer: open GitHub Desktop, type a short note in the Summary box at the bottom left, click Commit to main, then click Push origin.
  5. After files change on GitHub (for example, after you merge a pull request): click Fetch origin, then Pull origin.

Publish a website with GitHub Pages

Any repository with an index.html file in its top level can become a public website.

  1. On github.com, open your repository and click Settings, then Pages in the left menu.
  2. Under Build and deployment, set Source to Deploy from a branch, choose main and / (root), and click Save.
  3. Wait one or two minutes, then refresh the Pages screen. It shows your site's address, https://YOUR-USERNAME.github.io/REPOSITORY-NAME/. If the address shows a 404 page, wait two minutes and refresh again.

Every time you change a file on the main branch, GitHub rebuilds the site within a minute or two.

Part 2: Claude Code (terminal) + GitHub

Claude Code connects to GitHub through two command-line tools, git and gh, signed in once with your account. After that, Claude runs the GitHub commands for you and asks permission before each one. These steps assume Claude Code is already installed (see the Claude Code setup guide).

Install Git and the GitHub CLI

Commands to install Git and the GitHub CLI
SystemInstall command
macOSxcode-select --install (gives Git), then, once Homebrew is installed, brew install gh
WindowsGit for Windows (accept every default), then winget install --id GitHub.cli
Linux / Chromebook / WSLsudo apt install -y git, then follow GitHub's Linux install steps for gh

Mac students without Homebrew can download the gh installer from cli.github.com instead. Close and reopen the terminal, then confirm both work:

git --version
gh --version

Any version number means it worked.

Connect to GitHub

This is the same on every system.

  1. Sign in to GitHub from the terminal: 
    gh auth login
    Choose GitHub.com, then HTTPS, answer Yes to "Authenticate Git with your GitHub credentials," and pick Login with a web browser. Copy the one-time code shown, press Enter, and paste the code into the browser page. If no browser opens, go to github.com/login/device yourself.
  2. Tell Git who you are (use the email on your GitHub account): 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
  3. Check the connection: 
    gh auth status
    It should say "Logged in to github.com account (your username)."

Ask Claude to save and publish

Start Claude from your course folder (claude), build something, then ask in plain English:

  • Commit this to a new git repository. Then create a public GitHub repository called my-first-site and push it.
  • Turn on GitHub Pages for this repository from the main branch, and tell me the website address.
  • Commit and push this change.

You don't type the commands below; Claude proposes them. Knowing what they mean helps you decide whether to approve them.

Commands Claude will propose, and what each one does
You will seeWhat it does
git initStarts tracking changes in this folder
git add and git commit -m "..."Saves a snapshot of your files, with a short note
gh repo create my-first-site --public --source=. --pushCreates the repository on GitHub and uploads your files
gh api repos/.../pages ...Turns on GitHub Pages for the repository
git pushUploads your latest snapshot to GitHub

To work on a repository you already made on github.com, ask Claude: Clone my repository YOUR-USERNAME/dh_class into this folder.

Part 3: Claude Cowork + GitHub

Cowork writes files into your course folder; a second app uploads them to GitHub, so you stay in charge of every upload. Anthropic doesn't document a way for Cowork to save to GitHub on its own. These steps assume Cowork is set up with your course folder connected (see the Cowork setup guide).

How each system uploads Cowork's files to GitHub
SystemUpload to GitHub with
macOS, WindowsGitHub Desktop
Linux, ChromebookThe github.com website

macOS and Windows: GitHub Desktop

  1. Install GitHub Desktop and sign in (Part 1).
  2. Choose File > Add local repository, click Choose…, and pick your dh_class folder. GitHub Desktop says the folder isn't a repository yet: click create a repository, then Create repository.
  3. Click Publish repository. Uncheck Keep this code private if you'll publish a website from it, then click Publish repository again.
  4. From now on, after Cowork changes files, open GitHub Desktop. Your changed files appear on the Changes tab. Type a short note in the Summary box, click Commit to main, then click Push origin.

If you already made the repository on github.com in Part 1, use File > Clone repository instead of steps 2 and 3, and connect the cloned folder to Cowork.

Linux and Chromebook: github.com

  1. Make a repository on github.com (Part 1).
  2. Click Add file > Upload files, drag in the files Claude made (Chromebook: the files you downloaded from Cowork's Outputs), and click Commit changes.

Reading a repository in Cowork or chat

Claude can also read a GitHub repository: in a chat, click + and choose Add from GitHub. This copies the files in for Claude to look at, but Claude can't save changes back that way.

To publish a website from Cowork's files, ask Cowork for a one-file page called index.html, upload it, and turn on GitHub Pages (Part 1).

Part 4: Claude Code on the web + GitHub

Claude Code on the web works on a copy of your GitHub repository in the cloud, from any browser, with nothing installed. You connect GitHub once; Claude then pushes its changes to a new branch, and you merge them. You need a Claude Pro account and a repository (Part 1). Full screenshots are in the web setup guide.

Connect GitHub (once)

  1. Go to claude.ai/code and sign in with your own Pro account. If you see "Claude Code isn't available on your account," click Switch organization or sign in with your own account.
  2. Click Connect GitHub when Claude asks. If it doesn't ask, open the Repo menu and click Install the Claude GitHub App.
  3. GitHub asks Where do you want to install Claude? Sign in if asked, then click your own username.
  4. On the Install & Authorize Claude page, choose Only select repositories, click Select repositories, and pick your repository.
  5. Click Install & Authorize. If GitHub asks you to Confirm access, type your GitHub password and click Confirm. GitHub sends you back to Claude.

"Only select repositories" means Claude can see and change only the repositories you pick.

Choose a repository and run a task

  1. Below the message box, click Repo and pick your repository. Leave the branch on main, the environment on Auto, and the permission mode on Auto.
  2. Type a request, for example: Add a file called hello.md that says "Hello from Claude Code on the web."
  3. Claude works in the cloud and pushes its work to a new branch (a name like claude/bold-bohr-accbkk). Your main branch is not touched.
  4. The right panel shows Changes with counts like +1 −0. Click the counts to see exactly what changed.
  5. If you're happy, click Create PR (or tell Claude "yes, open a pull request").
  6. On GitHub, open the pull request and click Merge pull request, then Confirm merge. The change is now on main, and GitHub Pages (if it's on) rebuilds your site.
  7. To get the change onto your computer, open GitHub Desktop and click Fetch origin, then Pull origin.

You can close the browser tab while Claude works; come back to the session from claude.ai/code.

Changing access later

  • Add or remove repositories: on GitHub, open Settings → Applications → Installed GitHub Apps, click Configure next to Claude, and change the list.
  • Disconnect GitHub: go to claude.ai/customize/connectors and disconnect GitHub.

If Claude says it couldn't push (a "403" error and a Connect GitHub button), the app isn't installed on that repository. Your work is safe in the session: add the repository to the app, then tell Claude "I installed the app, please push again."

Part 5: The UT AI Hub + GitHub

The UT AI Hub gives active UT students, faculty, and staff private access to Claude and other AI models through the university. It is a chat in your browser: it has no GitHub connection, so Claude can't save anything to GitHub for you. Instead, you ask Claude to give you finished files and step-by-step upload instructions, and you copy them into GitHub yourself. It takes more work than Parts 2 to 4, but the result is the same: a repository and, if you like, a website.

I couldn't see the Hub's own screens while writing this, so these steps follow OIT's AI Hub guide. If a button name differs, look for the closest match.

Sign in and choose Claude

  1. Go to aihub.tennessee.edu and sign in with your UT Microsoft account (your UT email and password).
  2. Open the model drop-down list at the top of the chat and choose Anthropic Claude Sonnet. Avoid Claude Opus for everyday work: OIT says it can cost roughly 10 times as much of your monthly allowance.
  3. Your usage shows at the top right as a circle with a percentage inside. If it gets close to 100%, save your work and wait for next month, or keep your requests shorter.

The AI Hub keeps your data inside UT, but it is still not a place for passwords, other students' information, or anything you wouldn't want in a public repository. Follow UT's guidance chart for AI tools.

Start every project with this request

Paste this at the start of a new chat, then describe what you want to build. It tells Claude to give you output you can copy straight into GitHub.

I am using a chat without access to my computer or GitHub. I will copy your output into GitHub by hand, using only the github.com website (no terminal, no git commands).

For everything you build:
1. Give me every file complete, never partial, each in its own code block, with the exact file name (and folder, if any) on the line above it.
2. Keep a website to as few files as possible; a single index.html with the styling inside is best.
3. After the files, give numbered steps for putting them on github.com: which repository, Add file > Create new file, the exact file name to type, what to paste, and what to type in the commit message.
4. If GitHub Pages is needed, include the steps to turn it on.
5. When I ask for a change later, give me the whole updated file again, not just the changed lines.

Here is what I want to build:

Put Claude's output on GitHub

  1. Make a repository if you don't have one (Part 1).
  2. For each file Claude gives you, click the copy button on its code block (or select all the text in the block and copy it).
  3. On github.com, open your repository and click Add file > Create new file. Type the exact file name Claude gave (for example, index.html; for a folder, type images/ and the folder appears). Paste the text and click Commit changes.
  4. To change a file later, open it on github.com, click the pencil icon (Edit this file), select everything, paste Claude's new full version, and click Commit changes.
  5. Turn on GitHub Pages (Part 1) to publish a website.

To show Claude a file you already have, open it on github.com, click Raw, copy the text, and paste it into the chat. If the Hub lets you attach files in the chat, you can attach it instead.

Let GitHub do the building

For anything bigger than a file or two, pasting gets tedious. Ask Claude in the AI Hub to write a request for GitHub's own assistant instead, then follow Part 6 to hand it over:

Don't write the code yourself. Instead, write a clear request I can give to GitHub Copilot's coding agent to build this in my repository YOUR-USERNAME/REPOSITORY-NAME. Include what to build, which files to create or change, what it should look like, and how I will know it is finished. Put the request in one code block so I can copy it.

Part 6: Asking GitHub to build things (GitHub Copilot)

GitHub has its own AI assistant, GitHub Copilot. Its cloud agent can take a written request, make the changes in your repository, and open a pull request for you to review: the same result Claude Code on the web gives, but started from github.com. This is the easiest way to turn a request written in the UT AI Hub into real files, and it works with requests written by any Claude tool.

Get Copilot

Copilot planCostCan it build things in your repository?
Copilot StudentFree for verified studentsYes: includes Copilot in the cloud (the agent)
Copilot FreeFree for anyoneNo: chat only; you copy its answers in yourself
Copilot Pro and abovePaidYes

To get Copilot Student:

  1. Go to github.com/settings/education/benefits. Click Start an application and verify that you are a student (use your UT email; GitHub may ask for proof of enrollment).
  2. Once approved, under Free GitHub developer resources for students and teachers, click Learn more and follow the prompts to activate Copilot Student.
  3. Approval can take several days. If you see only paid options at github.com/settings/copilot, don't buy anything: wait a few days and check again.

GitHub's plans change often. Check the Copilot plans page if something here doesn't match.

Give Copilot a task

  1. On github.com, open your repository and click the Agents tab (or go to github.com/copilot).
  2. Check that your repository is selected in the prompt box.
  3. Paste your request (for example, the one Claude wrote for you in Part 5). End it with Open a pull request with the changes.
  4. Leave the environment on Cloud and click Start task.
  5. Copilot works for a few minutes; you can watch its progress or leave the page.

You can also assign an existing issue to Copilot: open the issue, click Assignees, and choose Copilot.

Review and merge Copilot's work

  1. When Copilot finishes, it opens a pull request and asks you to review it. Open it from the Pull requests tab.
  2. Click Files changed to see exactly what it did.
  3. Want changes? Write a comment on the pull request starting with @copilot, such as @copilot make the quotation larger, and it will update the pull request.
  4. When you're happy, click Merge pull request, then Confirm merge. If GitHub Pages is on, your site updates in a minute or two.

Check facts and quotations yourself before you merge. Copilot, like Claude, can get them wrong, and you are responsible for what you publish.

A good request

The clearer the request, the better the result. Whether you or Claude writes it, include:

  • What to build, in a sentence.
  • Which files to create or change (for example, index.html in the top level).
  • What it should look like or do, with specifics (colors, sections, wording).
  • How you'll know it's done (for example, "the page opens on a phone without sideways scrolling").
  • What not to touch (for example, "don't change any other files").
